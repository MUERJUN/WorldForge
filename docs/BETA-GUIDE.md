# WorldForge 公测指南（v0.7.4）

> 一个 JAR 装进游戏，在 Minecraft 里创建、测试、导出真正可用的独立 Mod。

## 环境要求

| 项目 | 要求 |
|------|------|
| Minecraft | Java 版 **1.21.1** |
| 加载器 | Fabric Loader **0.16.9+** |
| 依赖 | Fabric API **0.116.5+1.21.1** |
| Java | **21**（运行 MC 与导出构建都必须） |
| 磁盘 | 至少 2 GB（导出构建的 Gradle 缓存约 1 GB） |
| 网络 | 首次导出需联网下载 Gradle + Fabric Loom 依赖（约 100-200 MB，视网络 2-20 分钟） |
| AI 功能（可选） | 一个 DeepSeek 或 OpenAI API Key |

## 安装（3 步）

1. 安装 [Fabric Loader](https://fabricmc.net/use/installer/)，选择 1.21.1。
2. 把两个 JAR 放进 `.minecraft/mods/`：
   - `fabric-api-0.116.5+1.21.1.jar`
   - `worldforge-0.7.4.jar`
3. 启动游戏。进世界后按 **K** 打开 **AI 聊天**。
4. 第一次用先点聊天右上角 **⚙ 设置**，填服务商（DeepSeek / OpenAI 兼容）、URL、模型名、API Key
   → 「测试连接」确认通了 → 「保存」。单人游戏直接生效，不用重启。

> API Key 只保存在**服务端的** `config/worldforge/agent.json`，不上传、不进聊天历史、
> 不打包进导出的 JAR。旧 Studio 仍在 **L** 键里，普通玩家不需要进去。

## 5 分钟上手：造一把会召唤闪电的雷霆之剑

全程只用聊天，不用碰任何表单：

1. **按 K**，输入：「创建一把雷霆之剑，伤害 12，右键召唤闪电，冷却 5 秒」
2. AI 会先读你的上下文和已有能力，给出**操作摘要**，你在聊天里点**确认执行**
3. 确认后你背包里就有一把虚拟雷霆之剑（创造模式自动到手；生存模式用
   `/worldforge give thunder_sword`）
4. **测试**：手持右键——一道闪电落在你面前的地面，5 秒内再次右键被冷却挡住
5. **改手感**：再说「让它的伤害改成 20」→ 同样会先给摘要、等你确认 → 背包里的
   存量物品**立即**生效，不用重拿
6. **导出**：「把刚才的雷霆剑导出成一个独立 Mod」→ AI 先给**保留/转换/丢失**报告 →
   有降级就明确让你确认 → 真的跑一次 Gradle 构建 → 聊天里显示 JAR 名称和工作区相对路径
7. **分享**：把 `<GameDir>/worldforge/exports/` 里生成的 `my_thunder-1.0.0.jar` 发给朋友
   ——朋友只需 Fabric + Fabric API（不需要 WorldForge）就能用这把真正的雷霆之剑

### 聊天里你会看到什么

```
你: 给我的剑加个右键闪电，冷却 5 秒
AI: 我先看一下你手里的剑。
⚙ inspect_context: 已读取当前游戏上下文
⚙ update_item: 将修改物品 worldforge:thunder_sword 的定义
   （当前名称: 雷霆之剑，已有行为 1 条）。背包中该物品的存量实例会立即生效。
   [ 确认执行 ]  [ 取消 ]
你: 确认
⚙ update_item: 已修改物品 worldforge:thunder_sword（背包中的存量物品已即时生效）
AI: 好了，右键会召唤闪电，冷却 5 秒。
```

上面每一行都是**真实发生的事**，不是动画：成功只会在服务端真的改完之后才出现。

### v0.7.2 新能力：给原版物品附加行为

直到 v0.7.1，只有 WorldForge 虚拟物品才能做任何事。原版钻石剑只能当原版剑用。
v0.7.2 让**原版物品**也能参与行为引擎——**不替换物品**，只给它加一个能力。

**用法：**

1. 手持一把原版钻石剑（或任何原版物品）。
2. **按 K**，输入：「给我手里的剑加上右键加速」
3. AI 读取你手里的物品，发现是原版物品，提示可以附加行为。
4. 你在聊天里**确认执行**。
5. 物品的 **id、贴图、附魔、耐久全部不变**——只是多了行为能力。
6. 右键试试——**加速效果真的生效了**。
7. 说「撤销它」→ AI 移除嫁接 → 物品**完全还原**。

**限制：**

- 嫁接行为在合成/锻造时可能丢失（未做迁移逻辑）。
- 只能附加白名单内的行为（召唤闪电、施加效果、治疗、经验、传送、爆炸、点燃）。
- 不需要管理员权限，但仍然需要玩家明确确认。
- 即使没有配置 API Key，已有物品的行为仍能独立运行（行为引擎不依赖 AI Provider）。

### v0.7.3/v0.7.4：行为执行策略（服务器管理员必读）

「嫁接到自己物品」与「行为能否在世界里执行」是两个独立的权限。嫁接用 SELF 权限，
但行为的**实际执行**受服务端策略约束：

| 行为 | 默认 | 理由 |
|------|------|------|
| 治疗、经验、传送、对**自己**施加效果 | 允许 | 只影响玩家自己 |
| 对**其他实体**施加效果、召唤闪电、爆炸、点燃 | **拒绝** | 改变世界或影响他人（PvP） |

**服务器管理员配置**（v0.7.4）：

1. 配置文件：`config/worldforge/behavior-policy.json`（首次启动自动生成）。
2. 编辑 `allowedActions`（显式允许）与 `restrictedActions`（显式拒绝）。
   **restrictedActions 优先**：同一动作出现在两个列表时一律拒绝。
   两个列表都没写的动作按内置默认处理，未知动作一律拒绝。
3. 运行 `/wf policy reload`（需要 OP2 权限）立即生效；`/wf policy status` 查看当前策略。
4. **失败安全**：JSON 写错时重载会失败并**保留上一次有效策略**，不会静默放开限制；
   首次启动遇到坏配置则采用安全默认。修正文件后重新 reload 即可。
5. 策略在行为**触发时**校验：已嫁接的行为在策略变化后的下一次触发立即按新策略执行，
   被拒绝时玩家会收到明确提示。
6. v0.7.3 服务器只在本启动时读取一次该文件（修改需重启）；v0.7.4 起支持热重载。

### 多会话

右上角 **☰ 会话** 可以新建、切换、删除对话（例如「雷霆剑」「我的基地」「魔法系统」）。
每个对话有独立的消息、独立的待确认操作、独立的世界上下文，切换时**不会串台**。
历史存在 `<GameDir>/worldforge/chats/`，有限额、可删除；**读不出来的历史不会被静默清空**。

## 能力清单

### ✅ 导出后完整保留
- 物品/方块注册（独立 ID，与 WorldForge 无依赖）
- **召唤闪电**（右键真实生成闪电实体）
- **施加状态效果**（速度/力量/发光等，含时长与等级）
- **治疗**、**点燃**、**音效**、**粒子**
- **冷却时间**（per-player / per-block-instance，存档重启后保持，破坏方块即重置）
- 贴图（原版贴图映射）、语言文件、工具提示
- **右键触发**（on_use）的行为完整导出

### ⚠️ 导出时明确警告（需要确认，能力报告中列出）
- 物品属性数值（攻击力/护甲等）→ 报告为"没有等价实现"
- 周期方块（定时产出）→ 报告为"没有等价实现"

### ❌ 当前不支持（导出时明确列出，绝不静默丢弃）
- 动态实体、任意脚本/Java 执行
- 非 right-click 触发器（hit_entity / left_click 等——不会并入右键，明确报告为丢失）
- `experience`、`give_item` 动作（尚无代码生成实现）
- WorldForge 运行时专有 API
- 行为参数仅支持字符串/数字/布尔；嵌套结构在创建方案时拒绝

## 导出构建说明

- 导出生成完整 Gradle 工程（Gradle 8.14.3 + Fabric Loom 1.12.7），**构建工具自动按需下载**，不依赖你机器上的 Gradle。
- 需要 Java 21：导出前会自动检查 `java -version`。
- 构建超时 20 分钟（v0.7.0 从 10 分钟上调：首次导出要下载 Gradle 发行版、Fabric Loom、
  Minecraft 与映射，慢网络下十分钟不够）；取消/失败/超时会清理半成品 JAR，绝不留下"看似成功"的文件。
- 完整源码工程保留在输出目录，方便二次开发。

## 常见问题

| 现象 | 原因与解决 |
|------|-----------|
| 按 K 没反应 | 确认已进入单人世界；检查 mods 目录里 WorldForge JAR 完整（比对 SHA-256） |
| 按 K 打开的是聊天，但我想要旧编辑器 | 旧 Studio 仍在 **L** 键（或聊天右上角 ⚙）里 |
| 聊天提示「AI 未启用」 | 服务端没配 API Key：聊天 ⚙ 设置里填，或手改 `config/worldforge/agent.json` |
| 聊天卡在「等待你确认」 | 消息流里那条操作下方有 **确认执行 / 取消** 按钮；不确认就不会改世界 |
| 聊到一半断了线 | 会话历史在 `<GameDir>/worldforge/chats/`；待确认的操作在断线时**自动取消**，世界不会半改 |
| 客户端启动就崩 | 多半是**系统盘满**（构建缓存）。把 `GRADLE_USER_HOME` 换到项目盘再试 |
| 导出报"Java 编译环境不可用" | 安装 [JDK 21](https://adoptium.net/) 并确保 `java -version` 显示 21.x |
| 导出构建超时/失败 | 首次构建需下载依赖（2-20 分钟，v0.7.0 上限为 20 分钟）；失败后重试即可，已下载部分会复用。查看源码工程 `build.gradle` 排查 |
| 朋友用导出 JAR 报缺依赖 | 朋友也需要安装 Fabric API（这是 Fabric Mod 的标准依赖，不是 WorldForge） |
| AI 设置报 401/超时 | 检查 API Key 与网络；DeepSeek URL 填 `https://api.deepseek.com`，OpenAI 填 `https://api.openai.com` |
| 闪电/效果不触发 | 检查冷却是否未到；单人世界确认不是冒险模式 |
| 输出目录被拒绝 | 目录必须为空且不含符号链接（安全要求），换个新目录即可 |

## 已知限制（公测版）

- **AI 未配置时聊天不可用**（需要 API Key）
- **真实 DeepSeek/OpenAI 的端到端调用尚无独立验收**：本版验收用的是本地脚本化 Mock 模型，
  证明的是智能体链路，**不是**真实服务商的兼容性
- **不能给原版物品附加行为**，也不能改造原版方块：AI 会说明限制并给替代方案
- 修改方块定义影响**所有同 ID 实例**（共享定义），确认摘要里会写明
- 聊天历史有限额（50 个会话 / 每会话 500 条）；损坏的历史**不会被静默覆盖**
- 中文 GUI 文案在部分字体环境显示为方块（游戏语言设为简体中文可缓解）
- 高 GUI Scale（2/3）+ 854×480 小窗口下导出页布局为压缩版，建议 Scale 1 或更大窗口
- 导出的 Mod 支持 1.21.1；跨版本兼容未验证
